# Assumptions & Open Decisions

Everything below was decided because the spec left it open. Disagree with any row and the plan changes; rows marked **BLOCKER** must be resolved before the phase that needs them.

## Pinned decisions

| # | Area | Decision | Rationale |
|---|------|----------|-----------|
| A1 | LLM provider | One impl first: OpenAI-compatible `/chat/completions` (streaming + tool calling). Base URL, key, model from env. Covers OpenAI, OpenRouter, Groq, DeepSeek, vLLM/Ollama. | One code path, provider-agnostic by config; `LlmProvider` trait keeps room for others. |
| A2 | Embeddings | `fastembed` 7.1.1 + `EmbeddingModel::MultilingualE5Base` (`intfloat/multilingual-e5-base`), 768 dims → matches `vector(768)`. The `Embedder` impl MUST prepend `query: ` to queries and `passage: ` to documents (required by the model card; fastembed does not add them) — stored text stays unprefixed, only the vector input is prefixed. Chunk target lowered to ~480 tokens (model `max_length` is 512). Model pre-baked into the server image (1.06 GB fp32). `chunks` carries an `embedder` column and dedupes on `(embedder, content_hash)`. **Startup fail-fast:** the server reads `EMBEDDING_DIM` (default 768), asserts the configured `Embedder::dim()` equals it, and asserts it equals the `chunks.embedding` column dimension read from `information_schema` — a mismatch aborts boot instead of failing on the first ingest. | MIT, XLM-R covers Indonesian + English, exactly 768 dims so no schema change, cheapest strong-Indonesian encoder. Fallbacks: `EmbeddingGemma300MQ` (768 dims, 295 MB, Gemma licence) or `bge-m3` (1024 dims → new column + full re-embed; there is no widening cast, and `vector(1024)` costs ~1.33x the index payload). |
| A3 | Web search | **Composite**, all behind one `SearchProvider` trait, all server-side (`docs/SPEC.md:28` — no client ever calls a search API). `SEARCH_PROVIDER=composite` (default) tries, in order: **(1) academic APIs** — OpenAlex, ERIC, Crossref, DOAJ, arXiv, PubMed (keyless or free-key, official, no CAPTCHA, no ToS breach); **(2) SearXNG** — self-hosted compose service at `SEARXNG_URL`; **(3) fallback APIs** — Exa (`x-api-key`, `$10` free credit/mo ≈ 1,428 searches) then Tavily (`Authorization: Bearer tvly-…`, 1,000 free credits/mo). `SEARCH_PROVIDER` also accepts a single name (`academic`, `searxng`, `exa`, `tavily`) to pin one tier. A tier is only skipped on empty results or transport error, never on a single unresponsive engine. | Free web SERPs do not scale to a product: Tavily's 1,000 credits/mo is **~33 searches/day across all users**, and one pro user's `web_searches_per_day = 30` alone consumes it inside a month. Exa's `$10`/mo is ~1,428 searches but still metered. Academic APIs are free, official, and *higher quality for a study app* than a SERP. Measured 2026-10-11 from this network: of 8 SearXNG web engines only `google cse` returned results (`brave` 429, `duckduckgo` TLS-intercepted by the ISP, `startpage` CAPTCHA, `mojeek` timeout) — so SearXNG is a convenience tier, never the backbone. |
| A4 | Email | `lettre` over SMTP, env-configured; dev sink writes files. | No vendor lock; verification + reminders are the only uses. |
| A5 | Push | APNs token-based auth (`.p8`) + FCM v1 HTTP behind `PushProvider`. Desktop uses OS-native notifications from the shell, never a server push. | Matches platform rules; no third-party push service. |
| A6 | Timezone | Store UTC (`timestamptz`) + user IANA tz (default `Asia/Jakarta`). All local-date iteration via `chrono-tz`, never fixed offsets. | DST-safe planner and reminder scheduling. |
| A7 | Admin | `users.is_admin boolean not null default false`, seeded from `ADMIN_EMAIL` at startup. No roles/permissions table in MVP. | Cheapest thing that works; admin routes check the flag. |
| A8 | UUIDs | Client-generated UUIDv7 (Rust `uuid` v7 feature; JS `uuid` v7); server accepts client ids. Postgres `gen_random_uuid()` only as a fallback default. | Client-first writes offline need ids before the server sees them. |
| A9 | Credits | Balance = `sum(delta)` over `credit_ledger`; spend inside one transaction guarded by `pg_advisory_xact_lock(hashtext(user_id::text))`. Monthly bucket spent first, no rollover (configurable), purchased bucket never expires. | No balance column to keep consistent; advisory lock makes concurrent spend safe and testable. |
| A10 | Jobs | Single `jobs` table, `FOR UPDATE SKIP LOCKED` worker in the server binary, `run_at` scheduling, `attempts` + exponential backoff. Added `dedupe_key text unique` for singleton scheduled jobs (monthly grant, retention, reconciliation). No Redis. | Spec-mandated; `dedupe_key` prevents double-scheduling on restart. |
| A11 | Realtime | `/sync/stream` = per-connection task polling `max(seq)` for that user every ~2s and emitting `{seq}` on change. No cross-instance bus. | Works correctly with >1 server instance, no Redis pub/sub needed. |
| A12 | Rate limits | In-process token buckets per (user, route-class). Documented caveat: per-instance, not global. | MVP is one instance; swap to DB/Redis later behind a trait if needed. |
| A13 | Local cache encryption | `SQLCipher` behind config flag, **off by default**. Documented in `docs/ARCHITECTURE.md`. | Platform support varies; off keeps Phase 8 unblocked. |
| A14 | Web build | Online-first: TanStack Query in-memory cache only, no local DB, no outbox. | Spec-mandated. |
| A15 | Object storage | S3-compatible via `aws-sdk-s3`; MinIO in dev, any S3 in prod. Clients get short-lived presigned GET/PUT URLs only. | Standard, MinIO-compatible. |
| A16 | SSE shape | Named events: `token`, `citations`, `action`, `usage`, `done`, `error`. Client consumes via `fetch` + `ReadableStream` (no `EventSource`, since chat needs POST + auth header). | EventSource cannot POST or set `Authorization`. |
| A17 | Citation format | The model cites **numeric labels** — `[1]`, `[2]` for chunks and `[W1]`, `[W2]` for web results — never UUIDs. The server keeps a per-request `label -> chunk_id` map, validates every label against the context it sent, and drops unknown ones; the final `citations` SSE event carries the resolved structured array `[{type:"chunk",chunk_id,source_id,page}]`. Labels are per-request and never persisted. | Labels cost a few tokens instead of ~40 per citation, and a model cannot hallucinate a plausible-looking label that points at another user's chunk — an unknown label is simply dropped. `docs/SPEC.md` says `[[chunk:<uuid>]]`; this supersedes it (see Crate-list deviations). |
| A18 | PDF parsing | `pdfium-render` with the pdfium binary shipped in the server image (page numbers preserved); `lopdf` fallback for page count/metadata if pdfium fails to load. DOCX/PPTX via `zip` + `quick-xml`. | pdfium is the only reliable text+page extractor; lopdf as a soft-fail path. |
| A19 | Change-log retention | 90 days default (`CHANGE_LOG_RETENTION_DAYS`); tombstones kept at least as long; older cursors get `410 resync_required`. | Bounds table growth without breaking offline devices inside the window. |
| A20 | BYOK | Power only. Key encrypted (aes-gcm) in `user_api_keys`, never on device unencrypted, never logged. BYOK calls consume no credits and bypass the credit check but still count `usage_events` with `byok=true` and provider cost. | Spec-mandated; keeps margin reporting honest. |
| A21 | Plans source of truth | `config/plans.toml` loaded at startup into typed structs; the `plans` table is reconciled from it at boot and holds `entitlements jsonb` for auditing. Entitlement checks read the typed config, never the DB row. | One authority (the TOML), DB mirror for audit and FK integrity. |
| A22 | Access tokens | JWT (HS256, env secret), 15 min, carrying `user_id`, `device_id`, `session_family_id` — **not** plan. Entitlements load per request from `users.plan_id` + active subscription (5s in-process cache). | Plan changes (payment on another device) take effect immediately without token refresh. |
| A23 | Student discount | `.ac.id` (and configurable suffixes) email verified → `users.student_verified=true` → promo price auto-applied at checkout. | Spec-mandated. |
| A24 | Mobile purchase enforcement | Server rejects `/billing/checkout` for `platform in (ios, android)`; `GET /plans` on those platforms omits prices; client reads `config/billing_policy.toml` embedded at build time. Locked features show neutral copy. | Defense in depth for the app-store rule in the spec. |
| A25 | `web_sear` credit cost | `2` (spec text is truncated: `web_sear,`). Tunable in `config/plans.toml`. | The provider call itself is now ~free (A3: academic APIs are keyless, SearXNG is self-hosted), so this price no longer covers search — it covers the **fetched pages** injected as context (up to N pages × ~2k tokens) plus the citation-validation work. Keeping it non-zero is what stops "always on" web context from being the cheapest way to burn LLM budget, and it keeps the free tier's `web_searches_per_day = 3` meaningful. |
| A26 | Toolchain floors | Rust 1.94.1 (`rust-toolchain.toml`), Node 24 (`.nvmrc` + `engines`). | `sqlx` 0.9 needs Rust 1.94.0, `aws-sdk-s3` 1.152 needs 1.94.1; Vite 8 needs Node ≥22.12, React Router 8 ≥22.22, Vitest 5 accepts 22.12/24/26. |
| A27 | sqlx query style | Runtime `query_as`/`query_scalar` with explicit column lists for `chunks` (vector/tsvector) and the generic sync/entity paths; `query!`/`query_as!` macros elsewhere, never `SELECT *`. `SQLX_OFFLINE=true` + committed `.sqlx` in CI. | sqlx 0.9 does not support `vector`/`tsvector` in the compile-time macros, and runtime `query*()` now takes `impl SqlSafeStr` (only `&'static str`), so no dynamic SQL anywhere. |
| A28 | Frontend type/lint tooling | TypeScript 7.0.2 with an explicit tsconfig (`types: ["vite/client", "node"]`, `strict`); frontend lint = `tsc --noEmit` + `vite build`. No `typescript-eslint` in the MVP. | TS 7 has no programmatic API until 7.1, so eslint-style tooling would need an npm alias to `@typescript/typescript6`. Extra moving parts for no MVP value. |
| A29 | Local DB ownership | The Rust shell owns the SQLite cache/outbox via `rusqlite` 0.40.2 (`bundled`); `@tauri-apps/plugin-sql` is NOT used. | The sync engine, outbox and conflict rules are Rust-side; JS must not own the database. `plugin-sql` also pins sqlx 0.8, which would duplicate the driver stack next to sqlx 0.9. |
| A30 | Secure token storage | `keyring-core` 1.0.0 + per-platform stores wired by `cfg`: `apple-native-keyring-store` 1.0.2 (**feature `keychain` on macOS**, **feature `protected` on iOS** — iOS has no other store), `windows-native-keyring-store` 1.1.0, `android-native-keyring-store` 1.0.0. Only the refresh token is stored (Windows `CRED_MAX_CREDENTIAL_BLOB_SIZE` = 2560 bytes); the access token stays in memory. **Android needs no Kotlin shim**: `ndk-context` is already initialized before `main` by android-activity (via tao, which Tauri uses) — the store's own README lists Tauri Mobile as a framework that provides this. Writing our own `initializeNdkContext` call would be a *second* call, and `ndk_context::initialize_android_context` does `assert!(previous.is_none())`, i.e. it would panic at startup. Fallback only if a device prototype shows `Store::new()` returning `Err`: add the Kotlin shim then. | `keyring` 4.2.0 **defaults are desktop-only** (`Error::NoDefaultStore` on iOS/Android). `tauri-plugin-stronghold` is officially deprecated; `tauri-plugin-store` is plaintext; `tauri-plugin-keyring` 0.1.0 has no Android. API verified from the 1.0.0/1.0.2 crate sources: `set_default_store(Arc<CredentialStore>)`, `Store::new() -> Result<Arc<Self>>`, `Entry::{new,set_password,get_password,delete_credential}`, `Error::{NoEntry,NoDefaultStore}`. |
| A31 | Push notifications | No official Tauri push plugin exists. Phase 14 uses `tauri-plugin-notifications` (Choochmeque) 0.5.0-rc.14 — pin exactly and vendor it if the API moves, since it is pre-1.0 and single-maintainer. Budget a custom Swift/Kotlin plugin as the fallback. | The official `tauri-plugin-notification` **cannot** receive APNs/FCM (its iOS delegate skips `UNPushNotificationTrigger`; its Android manifest registers no FCM service). |
| A32 | Offline local notifications | Official `tauri-plugin-notification` 2.6.0 with `Schedule.at/interval/every` — it fires while the app is closed and offline on **both mobile platforms** (Android `AlarmManager` + `BOOT_COMPLETED` restore; iOS `UNUserNotificationCenter`). **Desktop has no offline parity:** the plugin ignores scheduling entirely (notify-rust), so the `Platform::schedule` contract is best-effort, and desktop reminders come from (a) server-sent push/in-app delivery on next launch, plus (b) an in-process `tokio` timer that only fires while the app is running. Phase 12's reminder engine must not assume cross-platform parity: it delivers *scheduled* reminders on mobile and *immediate/lazy* ones on desktop. Android delivery may be inexact without `SCHEDULE_EXACT_ALARM` (accepted); iOS caps pending scheduled notifications (commonly cited as 64, UNVERIFIED) so the client schedules only the next N and refills on foreground. | This is the only offline-capable reminder channel and it is local, not remote — desktop and web genuinely cannot match it, so the asymmetry is documented rather than papered over. |
| A33 | Background sync | The sync engine lives in Rust. Foreground sync on open/resume is the reliable path; Phase 14 adds one `BGAppRefreshTask` + one `BGProcessingTask` (iOS) and one periodic `WorkManager` job ≥15 min (Android) behind a native seam. Push is an opportunistic hint, never a schedule. | The SPA's JS **cannot** run while backgrounded or terminated on either platform (iOS suspends the web-content process; Android may kill cached processes). No plugin provides headless JS. |
| A34 | File intake | Desktop + Android: `tauri-plugin-dialog` 2.8.2 + `tauri-plugin-fs` 2.7.0 (URL-based APIs only for `content://`); Android copies the picked file into app storage immediately because `ACTION_GET_CONTENT` grants are transient. iOS share-sheet import needs a Share Extension + App Group (custom Swift, cannot launch the host app directly); plain "Open in…" works via `bundle.fileAssociations`. | No folder picker on mobile; iOS share sheet is the one piece with no config-only path. |
| A35 | Updates | `tauri-plugin-updater` 2.13.3 on desktop only (signed manifests); mobile updates ship through TestFlight/Play. | The plugin declares `ios: none`, `android: none`. |
| A36 | Tauri command cwd | `build.beforeDevCommand`/`beforeBuildCommand` run with cwd = the frontend dir derived from `frontendDist`. With `frontendDist = "../app/dist"` the cwd is `<root>/app`, so the commands are plain `npm run dev` / `npm run build`. | Verified in `tauri-cli` source (`dirs.frontend`), not guessed; avoids `--prefix` hacks that break depending on cwd. |

| A37 | Cheatsheet / PDF export | Server-side headless Chromium via `headless_chrome` 1.0.22 → A4 PDF from `templates/cheatsheet.v1.html`, with `print_background(true)`, `prefer_css_page_size(true)`, `generate_document_outline(true)`, `generate_tagged_pdf(true)`. The model emits **structured JSON blocks, never HTML**; `crates/core/src/render/` escapes every field and sanitises SVG against an element allowlist. Two jobs: `generate_cheatsheet` (JSON → HTML) and `render_cheatsheet_pdf` (HTML → PDF), so a PDF failure never discards a good cheatsheet. Plan-gated: free gets the HTML (browser print), pro/power get the server-rendered PDF — `pdf` is already in pro/power `export_formats` and absent from free. | Keeps the model unable to inject markup into a document that is printed and shared, and reuses one template for every cheatsheet. Chromium honours `@page` margin boxes **and** `@page :first` (verified by rendering the template in this repo), so header/page numbers are declarative CSS with CDP templates as the fallback. |
| A38 | Prompt versioning | Prompt modules live in `prompts/*.md` as versioned files compiled with `include_str!`; a shipped version is never edited, only superseded by `.v2`. The version string is logged on every `usage_events` row. `crates/core/tests/prompts.rs` fails CI on an undeclared variable, a leftover `{{...}}`, a missing grounding/security section, or a JSON example that does not parse. | Makes prompt quality and cost attributable to a specific version instead of guessed at, and makes the prompt contract machine-checked rather than maintained by discipline. |
| A39 | User-controlled prompt variables | `user_name`, `workspace_name`, `goal_title`, `task_title`, `notes`, `topic`, `capture_text` are wrapped by the composer in a `<user_context_data>` block labelled as data, never interpolated bare into the instruction stream. | A display name or workspace title is a user-editable string; interpolating it bare would let a user (or a workspace they were invited to) inject instructions through a field that looks like configuration. |
| A40 | Search caching and quota accounting | Every provider result set is cached in Postgres keyed by `(sha256(normalized_query), provider, max_results)` with a TTL (`SEARCH_CACHE_TTL_HOURS`, default 24); a cache hit serves the request **without** a provider call and **without** a second `web_sear` credit charge, but still writes a `usage_events` row with `cache_hit = true`. Cache rows are global, not per-user: a query string carries no user data, and per-user rows would multiply storage by the user count for no benefit. The tier that answered and any `unresponsive_engines` are recorded on the `usage_events` row, so silent degradation of the free path shows up in the admin margin report instead of being discovered by a user. | `web_searches_per_day = 3` on free makes a repeated query ("what is spaced repetition") common; re-billing it would burn the user's daily allowance and the provider quota on a question already answered. |
| A41 | Plan credit calibration | The spec's credit grants are kept as written (`free 60`, `pro 500`, `power 2000`) because they survive once search is free (A3) and the ceilings are enforced. What changes: **`ModelTier` gains `Cheapest`** and free uses it, while pro stays `Cheap` and power stays `Best`; `provider_cost_ceiling_usd` becomes a Phase-7 *enforced* stop, not a configured number; and `chat_message = 1` stays as-is. Measured cost per chat message at 2026-10-11 rates (IDR/USD 17,889): `$0.00119` on deepseek-v4.1-flash blended (off-peak `$0.00104` / peak `$0.00207`), `$0.00073` on a flash-lite class model. So free's full 60 credits cost ~`$0.044`/user/month, pro's 500 ~`$0.60` against `$0.56` revenue in the 100%-utilization worst case and ~`$0.24` at a realistic 40%, and power's 2000 ~`$2.39` against `$1.40`. **Known exposure:** the free tier is pure cost — at 10,000 free users it is ~`$438`/month (free model) or ~`$717`/month (pro model), and ~`$4,380` at 100,000 users. | The spec's numbers predate any token-cost arithmetic; the *reason* they are viable now is that search stopped being metered, not that the grants are generous. The cheapest tier is the single highest-leverage lever on the largest cost line, and making `ModelTier` `Ord` means the plan matrix test enforces "a higher plan never gets a cheaper model" by comparison rather than by three hand-written assertions that stop covering a new variant. **Levers, in order, if free-tier burn becomes real:** (1) lower `credits_per_month` for free toward 20, (2) tighten `provider_cost_ceiling_usd.free`, (3) gate free signup behind invite or `.ac.id` verification (A23 already builds the check). Do not raise prices to fix this — at Rp10,000 the price is already the product's main selling point. |

## Schema deviations from the spec (intentional, small)

| Change | Why |
|--------|-----|
| `users.is_admin boolean not null default false` | A7 — admin routes need an authority. |
| `events.task_id` gets `references tasks(id) on delete set null` | Spec left it an unconstrained uuid; a link without a FK drifts. **Ordering consequence:** `0012_tasks_*` must run before `0013_calendar_events`, or a fresh `sqlx migrate run` fails. |
| `jobs.dedupe_key text` + `unique` index (nullable) | A10 — singleton scheduled jobs (`monthly_grant`, `compact_change_log`, `poll_payment`) must not double-run across restarts or instances; a duplicate `monthly_grant` double-grants credits. |
| `pending_actions` gains `user_id`/`updated_at`/`deleted_at` + both sync triggers | The spec's DDL omits the `-- +sync` marker on `pending_actions`, but it is a synced entity: `Entity::PendingAction` (rank 16) requires it, and the spec says pending actions must be "visible and confirmable from any signed-in device". |
| New table `report_revisions` | The spec's conflict rules require that when a long text (`reports.body_md`) is edited on two devices, the losing version is kept "as a recoverable copy" — there is no table for it in the spec's DDL. It is server-side recovery data: no triggers, not synced, like billing internals. |
| `chunks.embedding` dimension is a single migration constant (default `768`) | A2 — must equal the configured embedder dimension; one place to change. |
| `chunks` gains an `embedder text not null` column, and the dedupe index becomes a **non-unique** `index on chunks (embedder, content_hash)` replacing the spec's plain `content_hash` index | Two reasons. (1) The spec's dedupe rule ("skip re-embedding chunks whose content_hash already exists") would silently reuse vectors from a *different* embedding model after a provider switch, leaving mixed vector spaces in one table and corrupting retrieval — so the lookup must be keyed on embedder identity. (2) It must **not** be a unique constraint: `chunks` has no `user_id` (it is scoped through `source_id → sources.workspace_id → workspaces.user_id`), so uniqueness would be global across all accounts — the first user to upload a widely-shared textbook would make ingestion *fail* for every other user who uploads the same file, and the error would leak content existence across tenants. `source_id` is `not null`, so chunks can never be shared rows anyway. Dedupe is implemented as a lookup that copies the existing embedding into the new row, scoped to the same user by joining through `sources`/`workspaces`. |
| `change_log.origin_device_id` is filled from `current_setting('app.device_id')` set per transaction | Avoids adding a device column to every sync table just for the log. |
| `log_change()` / `log_change_by_user()` take `pg_advisory_xact_lock(hashtext(user_id::text))` before inserting | Correctness, not tuning: `seq` is assigned by `nextval()` at insert time but rows become visible at commit time, so without the lock a pull cursor can permanently skip a lower seq that committed later. See roadmap § Sync protocol. |
| New table `cheatsheets` (+sync metadata) | The spec has no cheatsheet entity, but the print-PDF feature needs one to persist a generated document. Stores `title`, `scope`, `exam_date`, `depth`, `source_ids`, `status`, `error` and the object-storage keys for the rendered HTML and PDF. The rendered artifacts live in object storage (they are large and are not edited on-device), so only metadata syncs. |
| Citation format: numeric labels, not `[[chunk:<uuid>]]` | `docs/SPEC.md` § Retrieval says the model must cite by chunk ID. Sending raw UUIDs costs ~40 tokens per citation and lets a model fabricate a plausible-looking UUID; numeric labels are cheaper and an unknown label is trivially rejected against the context the server sent. `crates/core/src/citations.rs` is therefore a label→chunk resolver. The structured `messages.citations` form from the spec is unchanged. |
| `usage_events` gains `prompt_version text` | The prompt version that produced each action, so a quality or cost regression can be attributed to a prompt change rather than guessed at (A38). Nullable, because not every action calls a model. |
| `jobs.kind` gains `generate_cheatsheet`, `render_cheatsheet_pdf` | Split so a PDF-rendering failure does not discard a successfully generated cheatsheet; the HTML is still usable and printable from a browser. |

## Out of scope (confirmed from spec)

Apple IAP, Google Play Billing, auto-renewing billing, audio overviews, lecture recording/transcription, realtime collaboration, Mac App Store / Microsoft Store, Linux, widgets/watch apps, OCR/camera scanning, on-device LLMs, offline chat/generation/uploads, multiple chat threads per workspace, non-Google OAuth, LMS integrations, browser extension, Stripe/international payments.
