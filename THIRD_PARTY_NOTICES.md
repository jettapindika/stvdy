## Bundled assets

### Typefaces

Three families ship, self-hosted, in two copies: the SPA's `app/public/fonts/` (generated by
`scripts/fetch-fonts.mjs`) and the server's `assets/fonts/` (fetched by
`scripts/fetch-print-assets.sh` for the print template). Both directories are the authority
for what actually ships; this table is checked against them rather than against a design
document. **It previously named IBM Plex Sans and IBM Plex Mono, which no longer ship** —
the typefaces changed (A105) and the attribution did not follow, which is a compliance defect
in both directions: an attribution for fonts the product does not distribute, and none for
the three it does.

| Asset | Licence | Notes |
|---|---|---|
| Plus Jakarta Sans (600/700, latin + latin-ext) | SIL Open Font License 1.1 | Headings, SPA only: `app/public/fonts/plus-jakarta-sans-latin-*.woff2`. The print template does not name it, so `assets/fonts/` does not carry it. |
| Inter (400/500/600, latin + latin-ext) | SIL Open Font License 1.1 | UI and body text in the SPA, and the print template's body font — so it ships **twice**: `app/public/fonts/inter-*.woff2` and `assets/fonts/inter-*.woff2`. `app/src/fonts.css` records the same licence for the SPA copy. |
| JetBrains Mono (400/500, latin + latin-ext) | SIL Open Font License 1.1 | Page references, timestamps and hotkeys. Same two copies as Inter, for the same reason. |

All three are self-hosted because the app must render with no network: the desktop shell's
CSP allows no remote font origin, and the phone build is used on campus Wi-Fi that is often
down. latin-ext is kept because Indonesian source material needs characters outside basic
latin. The OFL permits bundling and redistribution, including in a commercial product,
provided the fonts are not sold on their own and the licence text and copyright notice
accompany them. **The licence text is not in this file** — see "Obligation before binaries
ship" below.

| Asset | Licence | Notes |
|---|---|---|
| KaTeX 0.19.0 (CSS, JS, woff2 fonts) | MIT | Used by `templates/cheatsheet.v1.html` to typeset print math. Vendored under `assets/katex/` and **served by the server** from `GET /assets/{*path}` (`rust-embed`), not fetched from a CDN: a render must not depend on a third-party origin being reachable, and the failure it caused was a PDF printing every formula as literal `$…$` (A339, A340). |

## Copyleft audit

Checked across the full resolved dependency graph, not just direct dependencies. Exactly one
crate offers a copyleft option and it is a disjunction:

- `r-efi` — `MIT OR Apache-2.0 OR LGPL-2.1-or-later`. Stvdy elects **MIT**, so no
  LGPL obligation attaches.

No crate dependency is GPL, AGPL, LGPL-only, SSPL, BUSL, or non-commercial. The
`proprietary` entries that appear in a licence scan are Stvdy's own crates.

**The container image changes this, and the change is not in the crate graph.** Three of the
binaries the image installs are not Rust crates and none of them appears in
`cargo metadata`:

- **LibreOffice is MPL-2.0**, which is a *file-level* copyleft. Distributing the binary
  requires making the source of the MPL-covered files available to recipients. Installing it
  into a private image that the operator runs on their own host is distribution *to that
  operator*, and Debian's package already discharges the source-availability by pointing at
  Debian's mirrors — so a self-hosted deployment is satisfied by the package metadata. **A
  redistributor of the image is not**: publishing the image on a registry means offering the
  corresponding source, and that obligation is theirs to meet. It is written here rather than
  discovered later because the image is otherwise a permissively-licensed stack and this is
  the one component that is not.
- **Chromium and pdfium aggregate dozens of third-party components** under their own terms,
  including some copyleft ones. Their notice files are in the image
  (`/usr/share/doc/chromium/copyright`, and the pdfium release's own `LICENSE`), and they must
  travel with any redistribution.
- **The ONNX Runtime (MIT) and the `intfloat/multilingual-e5-base` weights (MIT)** are
  permissive, and each still requires its notice to accompany the distribution.

The audit is therefore two audits now: the crate graph above, and the image's installed
packages. Re-run the first whenever a dependency is added or a version bumped — the audit is
a claim about the resolved graph, and the resolved graph changes without the manifests
changing. Re-run the second whenever a line is added to the `Dockerfile`'s `apt-get install`.

## Obligation before binaries ship (Phase 15)

This file **names** licences; it does not yet reproduce their texts. Every permissive licence
listed above (MIT, Apache-2.0, the SIL OFL, Unicode-3.0) requires its copyright notice and
permission text to accompany a binary distribution, and naming the licence is not the same as
including it. That obligation is not discharged by this file as it stands.

Phase 15 produces the binaries — a signed macOS `.dmg`, a signed Windows installer, an
Android APK, and the server image — so this stops being a gate and becomes a **release
step**. Before the first installer, store build or published image, generate the full texts:

```bash
cargo install cargo-about
cargo about generate about.hbs > THIRD_PARTY_LICENSES.md   # Rust side
npx license-checker --production --json > /tmp/npm-licences.json  # npm side
```

and ship the result alongside each artifact: inside the `.dmg` and the NSIS installer as a
file the installer writes, in the app bundle's own notices screen or a `NOTICES.txt` beside
it, and — for the image — as the packages' own `/usr/share/doc/*/copyright` files, which
already ship. The font and KaTeX texts come from the upstream releases
(`assets/checksums.txt` names each file's source URL), and the KaTeX and OFL texts must be
added to the generated file by hand, because neither `cargo-about` nor `license-checker`
sees a vendored `.woff2`.

Do this in the same change that adds code signing, so the two cannot drift apart.
